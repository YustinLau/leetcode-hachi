## leetcode 1183 Maximum Number of Ones

面对像 **1183. 矩阵中 1 的最大数量** 这种题目，你最初想用 DP 是非常自然的反应，因为“最大数量”、“最优解”通常是 DP 的地盘。

但在写不出递归方程时，我们需要一套**“破局思维”**。这道题实际上是一个典型的**从“局部约束”推导“全局贪心”**的题目。

---

### 1. 破局：从“滑动窗口”到“周期性”
题目要求：**每一个** $sideLength \times sideLength$ 的子矩阵内，1 的个数不能超过 `maxOnes`。

* **核心直觉**：为了让全局 1 最多，我们应该把 1 放在那些**被重复计算次数最多**的位置。
* **周期性规律**：如果我们在 $(r, c)$ 放置一个 1，那么为了满足所有子矩阵的约束，最理想的情况是这个 1 在整个大矩阵中呈**周期性出现**。这个周期就是 $sideLength$。
    > 也就是说，如果位置 $(r, c)$ 放了 1，那么所有满足 $(r \% sideLength, c \% sideLength)$ 相同的位置，都是“同类”位置。

---

### 2. 算法思维：贪心 + 计数
既然所有位置都可以按 $(r \pmod L, c \pmod L)$ 分成 $L^2$ 个格子（这里 $L = sideLength$），那么：

1.  **统计每个格子的“贡献度”**：
    计算在大矩阵中，有多少个坐标 $(i, j)$ 满足 $i \pmod L = r$ 且 $j \pmod L = c$。
    * 比如左上角 $(0,0)$ 这个格子，在整个大矩阵中出现的次数可能比右下角的格子多。
2.  **贪心选择**：
    我们要选出出现次数最多的前 `maxOnes` 个格子，把 1 全部填在这些格子上。

---

### 3. 数据结构选用：为什么不需要 DP？
* **不需要状态转移**：因为每个位置的贡献是独立的，不取决于相邻格子的具体分布，只取决于它的坐标规律。
* **选用优先队列（Heap）或排序**：我们需要找出“前 K 个最大值”，这正是堆或 `sort` 的强项。

---

### 4. 代码实现逻辑

```cpp
int maximumNumberOfOnes(int width, int height, int sideLength, int maxOnes) {
    // 1. 统计在 L * L 的小块中，每个相对位置在大矩阵中出现的次数
    vector<int> counts;
    for (int r = 0; r < sideLength; r++) {
        for (int c = 0; c < sideLength; c++) {
            // 计算有多少个 i 满足 i % L == r
            int rowCount = (width - r - 1) / sideLength + 1;
            // 计算有多少个 j 满足 j % L == c
            int colCount = (height - c - 1) / sideLength + 1;
            counts.push_back(rowCount * colCount);
        }
    }

    // 2. 排序，选出贡献度最大的前 maxOnes 个
    sort(counts.begin(), counts.end(), greater<int>());

    int res = 0;
    for (int i = 0; i < maxOnes; i++) {
        res += counts[i];
    }
    return res;
}
```

### 🛡️ 教练复盘：如何识别这类题？

当你遇到这类“子矩阵/子数组约束”题目时，可以按照这个路径思考：
1.  **找重复**：如果我在 $A$ 点放东西，它会影响哪些子矩阵？
2.  **找等价性**：有没有哪些点在约束下是“同命运”的？（通常是取模结果相同的点）。
3.  **算贡献**：每个等价类在全局出现了几次？
4.  **选最优**：用贪心策略选出贡献最大的。

**这就是从“尝试写 DP”到“发现贪心规律”的进化过程。**

* 这种**“镜像等价”**的思考方式，和今天这道矩阵题的**“取模等价”**本质上是一脉相承的。

**你想看看对称二叉树的递归（DFS）是如何巧妙对齐这两个“镜像点”的吗？**

这是一个非常棒的思维碰撞点！你的疑惑在于对**“重复计算”**这个词的理解。

让我们理清一个关键逻辑：**“被子矩阵覆盖”**不等于**“违反约束”**。

### 1. 核心矛盾：约束 vs. 贡献

* **约束（限制）**：每一个 $L \times L$ 的区域里，1 的总数不能超过 `maxOnes`。
* **贡献（我们的目标）**：我们要让整个大矩阵里的 1 尽可能多。

想象大矩阵是一个大地板，你可以往上面贴磁铁（1）。每一个 $L \times L$ 的透明框（滑动窗口）压在地板上时，框里的磁铁不能超过 `maxOnes` 个。

**重点来了：**
如果你在地板上的 $(r, c)$ 位置放了一个磁铁，由于窗口是在地板上**滑动**的，这个磁铁会被**很多个不同的窗口**数到。
* **重复计算多** = 这一颗磁铁为多个窗口“贡献”了 1 的名额。
* **重点**：既然每个窗口的名额是有限的（`maxOnes`），我们当然希望我们放下去的每一颗磁铁，都能在**尽可能多**的窗口里占据名额，这样我们就能用最少的磁铁布局，撑起最大的全局总量。

---

### 2. 为什么是取模 $(r, c)$？

题目规定任何 $L \times L$ 的窗口里 1 不超过 `maxOnes`。
最稳妥、效率最高的放法是**周期性放置**。

假设 $L=3, maxOnes=1$。
如果你在 $(0,0)$ 放了一个 1。为了不违反约束，下一个 1 最快只能放在 $(0,3), (3,0)$ 或 $(3,3)$。
你会发现，大矩阵被切成了无数个 $3 \times 3$ 的小方块。你在每个小方块的**相对位置** $(0,0)$ 放一个 1，绝对不会违反任何一个滑动窗口的约束。

---

### 3. “重复计算次数最多”到底指什么？

大矩阵的尺寸（`width`, `height`）往往不是 $L$ 的整数倍。这就导致了**不公平**。

举个例子：大矩阵 $4 \times 4$，小窗口 $3 \times 3$ ($L=3$)。
大矩阵可以切成如下坐标：
```
(0,0) (0,1) (0,2) | (0,3)
(1,0) (1,1) (1,2) | (1,3)
(2,0) (2,1) (2,2) | (2,3)
------------------+------
(3,0) (3,1) (3,2) | (3,3)
```
* 如果你在每个 $3 \times 3$ 区域的相对位置 **$(0,0)$** 放 1：你会放在 $(0,0)$ 和 $(3,0)$ 和 $(0,3)$ 和 $(3,3)$。总共 **4 个**。
* 如果你在每个 $3 \times 3$ 区域的相对位置 **$(2,2)$** 放 1：你只能放在 $(2,2)$ 这 **1 个**。

**为什么？**
因为 $(0,0)$ 这个相对位置在大矩阵里出现了 4 次，而 $(2,2)$ 只出现了 1 次。
为了让全局 1 最多，我们肯定优先选那些在大矩阵里**出现次数（即重复频率）最高**的相对位置 $(r, c)$ 来放磁铁。

---

### 4. 总结贪心策略

1.  把大矩阵看作由无数个 $L \times L$ 的小格子铺成的。
2.  统计每一个相对坐标 $(r, c)$（其中 $0 \le r, c < L$）在大矩阵中一共出现了多少次。
3.  这些出现次数就是这个位置的**“权值”**。
4.  我们一共有 `maxOnes` 个名额。
5.  **贪心**：选权值最大的前 `maxOnes` 个位置，把 1 填满。

---

### 💡 类比理解

这就像是在**排班**：
* **约束**：每个小时（窗口）公司只能有 `maxOnes` 个人上班。
* **目标**：总工时（全局 1）最长。
* **策略**：如果某个人精力无限，我们肯定让他去那些“跨度最大、被计算次数最多”的班次里待着。

**现在对这个“重复计算”和“权值”的逻辑有没有清晰一些？**

这种“找相对位置”和“镜像对齐”的直觉，其实和 **[101. 对称二叉树]** 异曲同工。对称二叉树是让你在左子树找一个位置，然后在右子树找一个**对应的对称位置**。

**既然矩阵的“等价点”你已经摸透了，我们要不要看看二叉树里的“镜像等价点”是怎么判断的？**

你的思考非常深入，但这里有一个微妙的**逻辑反转**，也是这道题最“绕”的地方。

### 1. 关键修正：1 是被“共享”的，而不是被“消耗”的

你提到的“1 的位置尽量不要被子格子重复用”，其实**恰恰相反**。

想象一下：如果你在大矩阵的某个坐标 $(x, y)$ 放了一个 1。
* 每一个包含这个坐标 $(x, y)$ 的 $L \times L$ 子格子，都会把这个 1 计入自己的 `maxOnes` 名额中。
* 这个 1 就像一个**共享资源**：它同时为多个子格子贡献了“1 个 1”的额度。

**我们的目标是：** 用最少的“1”，填满尽量多子格子的 `maxOnes` 额度。或者反过来说，让大矩阵里的每一个“1”，都能在尽可能多的 $L \times L$ 子格子中“发光发热”。

---

### 2. 相对位置的“魔法”

正如你所说，我们把大矩阵划分为无数个 $L \times L$ 的区域。
* 每个坐标 $(i, j)$ 都可以映射到一个**相对位置** $(r, c)$，其中 $r = i \pmod L, c = j \pmod L$。
* **神奇的特性**：如果你只在 $L \times L$ 的小格子里选 `maxOnes` 个相对位置放 1，并把这个模式**铺满**整个大矩阵，那么**无论你从哪里截取一个 $L \times L$ 的子格子，它里面的 1 永远恰好等于 `maxOnes`。**（这就是滑动窗口的周期性原理）。

---

### 3. 为什么要选“重复次数多”的相对位置？

虽然每个 $L \times L$ 的窗口里 1 的数量都被限制在了 `maxOnes`，但由于大矩阵的宽高（Width, Height）通常不是 $L$ 的整数倍，导致某些相对位置在全局出现的次数是不一样的。

**举个极端的例子：**
大矩阵 $4 \times 4$，小窗口 $3 \times 3$ ($L=3$)。
我们只能在 $3 \times 3$ 的相对坐标系里选 **1 个**位置放 1（假设 `maxOnes = 1`）。

* **方案 A：选相对位置 $(0,0)$**
  你在全局坐标 $(0,0)$ 和 $(3,0), (0,3), (3,3)$ 放了 1。
  **总数 = 4**。
* **方案 B：选相对位置 $(2,2)$**
  你在全局坐标 $(2,2)$ 放了 1。注意，下一个周期位置 $(2,5)$ 已经超出大矩阵边界了。
  **总数 = 1**。

**结论**：方案 A 和 B 都完美满足“任何 $3 \times 3$ 区域内 1 不超过 1 个”的约束，但方案 A 得到的全局 1 更多！这就是为什么要统计每个相对位置在大矩阵里出现了几次（即权值），然后贪心地选权值最大的。

---

### 🛡️ 教练的总结

1.  **分块**：将坐标映射到 $L \times L$ 的相对坐标 $(i\%L, j\%L)$。
2.  **统计**：看哪个相对坐标在整个大矩阵里对应的“实地坐标”最多。
3.  **贪心**：你有 `maxOnes` 个名额，当然要给那些“露脸次数最多”的相对坐标。

### 1. 为什么是 `rowCount * colCount`？

这是典型的**笛卡尔积（组合）**原理。

想象我们要计算相对位置 $(r, c)$ 在大矩阵里出现了多少次：
* **行方向**：在宽度为 `width` 的地板上，坐标 $0, 1, 2, \dots, width-1$ 中，有多少个索引 $i$ 满足 $i \pmod L = r$？这个数量就是 `rowCount`。
* **列方向**：在高度为 `height` 的地板上，有多少个索引 $j$ 满足 $j \pmod L = c$？这个数量就是 `colCount`。

**为什么相乘？**
因为只要一个坐标 $(i, j)$ 同时满足 $i \pmod L = r$ **且** $j \pmod L = c$，它就是我们要找的那个“点”。
对于每一个符合条件的“行索引”，它都可以和每一个符合条件的“列索引”组合成一个唯一的坐标点。所以，这个相对位置在全局出现的总次数（即贡献值）就是 `rowCount` 乘以 `colCount`。

### 2. 启发：从“局部约束”到“全局最优”

这道题带给我们的深度启发可以总结为：**“周期性对称打破了复杂性”**。

* **空间平移不变性**：当约束条件在整个空间内是“平移触发”（比如滑动窗口）时，最优解往往具有周期性。
* **约束转换**：把一个**动态滑动**的约束（每个 $L \times L$ 框），转换成了一个**静态固定**的配额（在一个 $L \times L$ 周期内选 $K$ 个点）。
* **贡献度量化**：当每个决策点（填 1）对目标的贡献不均等时，优先选择“性价比”（权值）最高的点。

## leetcode 3163.String Compression III

你已经敏锐地抓住了这道题的核心约束：**“连续相同字符”**且**“长度不超过 9”**。

你提到的编译错误和逻辑偏差，主要是因为 `unordered_map` 和 C++ 字符串转换的处理方式。在处理这种**相邻重复**的问题时，其实不需要用到 `map`（因为 `map` 会打乱顺序或记录全局频率），直接用**双指针**或**单次循环计数**会更清晰。

### 🔍 你的初稿问题诊断

1.  **越界风险**：`word[i+1]` 在循环到最后一个字符时会溢出。
2.  **类型转换错误**：`string(record[word[i]])` 这种写法在 C++ 中是错误的。将数字 `9` 转为字符 `'9'` 应该用 `to_string()` 或者直接 `+ '0'`。
3.  **Map 的逻辑误区**：`map` 记录的是全局出现次数，但题目要求的是**连续**出现。比如 `aaabbaa`，中间的 `b` 断开了 `a`，你的 `map` 可能会把前后的 `a` 算在一起。

---

### 🚀 优化思路：贪心计数

我们只需要维持一个当前的计数器，只要字符没变且没到 9，就一直往后走。

#### 💻 修正后的代码：

```cpp
string compressedString(string word) {
    string comp = "";
    int n = word.size();
    int i = 0;
    
    while (i < n) {
        char c = word[i];
        int count = 0;
        
        // 只要字符相同 且 计数小于 9 且 不越界
        while (i < n && word[i] == c && count < 9) {
            count++;
            i++;
        }
        
        // 拼接：次数 + 字符
        comp += to_string(count) + c;
    }
    
    return comp;
}
```

---

### 🛡️ 教练复盘：为什么这样更优雅？

* **双层循环的艺术**：外层 `while` 控制总进度，内层 `while` 负责“吃掉”相同且符合长度的字符。这种结构在处理**分组数据**时非常稳健。
* **空间优化**：舍弃了 `unordered_map`，空间复杂度从 $O(\Sigma)$ 降到了 $O(1)$（不计返回结果）。
* **避免越界**：由于我们在内层 `while` 里实时检查 `i < n`，完全避开了 `word[i+1]` 的溢出风险。

## leetcode 151 Reverse Words in a String

这个思路非常直观且有效，尤其是在你已经熟练掌握了**栈（Stack）**和**指针遍历**的情况下。

### 🔍 算法评价：这是一个经典的“空间换时间”方案

你的思路本质上是利用了栈 **“后进先出（LIFO）”** 的特性来完成单词的翻转。

**优点：**
1.  **逻辑清晰**：处理“逆序”问题时，栈是最自然的选择。
2.  **易于实现**：通过指针遍历配合 `string` 暂存单词，逻辑链条很完整。
3.  **处理空格稳健**：只要你在压栈前判断一下单词是否为空，就能完美解决“中间有多个连续空格”的问题。

**缺点：**
1.  **额外空间**：你需要 $O(N)$ 的空间来存储栈里的单词。
2.  **字符串拼接开销**：如果频繁进行 `result += s + " "`，在某些语言中可能会产生大量的临时字符串（不过在 C++ 中使用 `std::string` 性能尚可）。

---

### 🚀 职业选手的优化：双指针与局部翻转

在面试中，面试官经常会追加一个挑战：**“能否不使用额外的栈空间，实现 $O(1)$ 的原地空间复杂度？”**（假设输入的 `s` 可以直接修改）。

这种解法的思路非常巧妙，被称为 **“三步翻转法”**：

1.  **清理空格**：移除首尾以及中间多余的空格（用双指针原地移动）。
2.  **整体翻转**：把整个字符串翻转过来。例如 `"the sky is blue"` $\rightarrow$ `"eulb si yks eht"`。
3.  **局部翻转**：遍历字符串，把每一个单词再翻转回来。例如 `"eulb"` $\rightarrow$ `"blue"`。

---

### 💻 按照你的思路（栈）实现的 C++ 代码

为了防止你遇到编译或边界问题，我帮你把你刚才的逻辑具体化：

```cpp
string reverseWords(string s) {
    int left = 0, right = s.size() - 1;
    // 1. 去除首尾空格
    while (left <= right && s[left] == ' ') left++;
    while (left <= right && s[right] == ' ') right--;

    stack<string> st;
    string word;
    
    // 2. 遍历并压栈
    while (left <= right) {
        if (s[left] != ' ') {
            word += s[left];
        } else if (!word.empty()) { // 遇到空格且当前单词不为空
            st.push(word);
            word = "";
        }
        left++;
    }
    st.push(word); // 压入最后一个单词

    // 3. 出栈拼接
    string result;
    while (!st.empty()) {
        result += st.top();
        st.pop();
        if (!st.empty()) result += " ";
    }
    return result;
}
```

提到 151 题的双指针解法，这通常是面试官最欣赏的 **“原地修改（In-place）”** 思路。虽然 C++ 的 `string` 长度缩减不完全算 $O(1)$ 额外空间，但这种逻辑展现了你对内存操作的精准控制。

这个解法可以拆解为 **“三大步”**，我们直接在原字符串上“动手术”：

---

### 第一步：移除多余空格（快慢指针）
我们不需要 `unordered_map` 或栈，直接用两个指针 `slow` 和 `fast`。
* `fast` 往后跳过所有多余空格。
* `slow` 负责把有效的字符“洗”到前面。

```cpp
void removeExtraSpaces(string& s) {
    int slow = 0, fast = 0;
    while (fast < s.size()) {
        if (s[fast] != ' ') { // 遇到单词字符
            if (slow != 0) s[slow++] = ' '; // 单词间补一个空格
            while (fast < s.size() && s[fast] != ' ') {
                s[slow++] = s[fast++];
            }
        }
        fast++;
    }
    s.resize(slow); // 重新调整大小，砍掉后面多余的尾巴
}
```

---

### 第二步：整体反转
把整个清理干净的字符串翻转过来。这一步是为了让 **最后一个单词跑到最前面**。
* 例如：`"the sky is blue"` $\rightarrow$ `"eulb si yks eht"`

```cpp
reverse(s.begin(), s.end());
```

---

### 第三步：局部反转单词
此时单词的位置对了，但单词内部的字母顺序是反的（比如 `blue` 变成了 `eulb`）。我们需要再次遍历，把每个单词转回来。

```cpp
for (int i = 0; i < s.size(); i++) {
    int j = i;
    while (j < s.size() && s[j] != ' ') j++; // 找到单词末尾
    reverse(s.begin() + i, s.begin() + j);  // 翻转这个单词
    i = j; // 跳到下一个位置
}
```

---

### 🔍 为什么这个写法更“Hardcore”？

1. **零额外容器**：不像你的栈解法需要存下所有 `string` 单词，这个解法只用了几个 `int` 变量。
2. **时间效率**：整个字符串只被遍历了大约 3 遍（去空格、总翻转、分单词翻转），时间复杂度是稳稳的 $O(N)$。
3. **内核感**：在 Linux 内核开发或 C 语言环境下，没有 `std::stack` 可用时，这种对 `char*` 的直接操作就是唯一的标准答案。

## leetcode 88 Merge Sorted Array

你提到的“内存限制”报错，大概率是因为代码中的一个**逻辑死循环**导致的内存溢出（虽然表面看是数组越界或 `push_back` 过多）。

### 🔍 你的代码“死穴”在哪里？

1. **三目运算符的逻辑错误**：
   ```cpp
   p1 = (nums1[p1] < nums2[p2] ? p1 + 1 : p1);
   p2 = (nums1[p1] < nums2[p2] ? p2 + 1 : p2);
   ```
   你先更新了 `p1`，接着在更新 `p2` 的判别式里又用了**已经更新过**的 `p1`。这会导致逻辑错乱，甚至可能出现 `p1` 和 `p2` 都不自增的情况，从而引发死循环。
2. **`push_back` 与预分配冲突**：你初始化了 `vector<int> result(m + n)`，这已经有了 $m+n$ 个 `0`。后面再 `push_back`，`result` 的长度会变成 $2(m+n)$，最后的赋值循环就会越界。

---

### 🚀 职业选手的神技：从后往前填（逆向双指针）

这道题最优雅的解法是不开辟任何 `result` 空间，直接在 `nums1` 上原地操作。

**为什么从前往后填不行？** 因为会覆盖掉 `nums1` 还没处理的数据。
**为什么从后往前填可以？** 因为 `nums1` 后半部分本来就是空的（全为 0），我们把最大的数先放到最后面，绝对不会吵醒前面的“数据”。

#### 💻 逆向双指针实现：

```cpp
void merge(vector<int>& nums1, int m, vector<int>& nums2, int n) {
    int p1 = m - 1;      // nums1 的有效末尾
    int p2 = n - 1;      // nums2 的末尾
    int p = m + n - 1;   // nums1 的整体末尾（填数的位置）

    while (p1 >= 0 && p2 >= 0) {
        // 谁大谁往后站
        if (nums1[p1] > nums2[p2]) {
            nums1[p--] = nums1[p1--];
        } else {
            nums1[p--] = nums2[p2--];
        }
    }

    // 如果 nums2 还没填完，直接拷过去（nums1 没填完不用管，因为已经在位置上了）
    while (p2 >= 0) {
        nums1[p--] = nums2[p2--];
    }
}
```

---

### 🛡️ 教练复盘：思维的相似性

这道题其实是 **23. 合并 K 个升序链表** 的简化版。
* **23 题**：用堆来找 $K$ 个头里的最小值，从前往后接。
* **88 题**：只有 2 个数组，利用**尾部空余空间**，从后往前填最大值。

**这种“逆向思维”在处理有容量限制的数组题时，往往能把空间复杂度从 $O(N)$ 直接压到 $O(1)$。**
