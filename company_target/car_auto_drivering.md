## leetcode 1004

你的想法非常敏锐，**回溯（Backtracking）** 确实能穷举出所有翻转的可能，但在处理这种“连续子区间”的问题时，回溯往往会带来巨大的开销。

### 🔍 为什么回溯（Backtracking）不是最优解？

* **复杂度爆炸**：回溯本质上是深度优先搜索（DFS），它会尝试“翻转这个0”和“不翻转这个0”两种路径。对于长度为 $N$ 的数组，这会产生接近 $2^N$ 的状态空间，导致 **Time Limit Exceeded (TLE)**。
* **重复计算**：你会发现，为了找长度为 5 的区间和长度为 6 的区间，回溯会反复扫描相同的子数组。

### 🚀 降维打击：滑动窗口（Sliding Window）

这道题的本质是：**找出一个最长的子区间，其中包含 0 的个数不超过 $K$。**

想象你在数组上拉了一根**橡皮筋**（窗口）：
1.  **右边界 `right` 扩张**：只要遇到 0，我们就消耗一个 $K$ 的名额。
2.  **约束检查**：如果 $K$ 用完了（变成负数），说明现在的窗口“太贪心”了，装了超过 $K$ 个 0。
3.  **左边界 `left` 收缩**：我们开始吐出左边的元素。如果吐出来的是 0，就把 $K$ 的名额还回去。
4.  **记录最大值**：在整个过程中，窗口宽度的最大值就是答案。

#### 💻 C++ 实现

```cpp
int longestOnes(vector<int>& nums, int k) {
    int left = 0, right = 0;
    int maxLen = 0;
    int zeroCount = 0; // 记录当前窗口内 0 的个数

    for (right = 0; right < nums.size(); right++) {
        if (nums[right] == 0) {
            zeroCount++;
        }

        // 当 0 的个数超过了允许的 k，左边界就要开始收缩了
        while (zeroCount > k) {
            if (nums[left] == 0) {
                zeroCount--;
            }
            left++;
        }x

        // 窗口内的 0 始终不超过 k，更新最大长度
        maxLen = max(maxLen, right - left + 1);
    }
    return maxLen;
}
```

### 🛡️ 教练复盘：什么时候用滑动窗口？

当你看到题目要求：
1.  **最大/最小/最长/最短**
2.  **子数组/子串（连续的）**
3.  **有一定的约束条件（比如翻转 $K$ 次，或者包含某些字符）**

这时候，**滑动窗口**几乎是唯一的 $O(N)$ 满分答案。它比回溯强在它不需要“回头”，左右指针各走一遍数组就收工了。

## leetcode 215 Kth Largest Element in an Array

维护k个长度的最小堆，返回堆顶元素你的直觉非常准，用 **`priority_queue` 维护一个大小为 $K$ 的最小堆** 确实是这道题的“标准教科书答案”。这种解法的时间复杂度是 $O(N \log K)$，空间复杂度是 $O(K)$。

### 1. 为什么面试官不满足于“堆”？

虽然堆很优秀，但面试官会追加两个挑战：
1.  **能不能做到 $O(N)$ 的期望时间复杂度？**（堆是 $O(N \log K)$）。
2.  **能不能原地修改（In-place）？**（堆需要 $O(K)$ 的额外空间）。

这时候，你就必须祭出 **Quick Select**。

---

### 2. 核心算法：快速选择 (Quick Select)

这个算法基于 **快速排序 (Quick Sort)** 的 `partition` 思想。
* **原理**：在快排中，每进行一次 `partition`，选定的 `pivot` 就会被放到它最终排好序的位置上。
* **优化**：我们不需要像快排那样递归处理左右两边。
    * 如果 `pivot` 的索引正好是 `n - k`，那它就是我们要找的数。
    * 如果索引比 `n - k` 小，我们只去**右半部分**找。
    * 如果索引比 `n - k` 大，我们只去**左半部分**找。

**这种“减治法”将复杂度从 $O(N \log N)$ 降低到了期望 $O(N)$。**

---

### 3. 如果考到这道题，除了写代码还有什么要求？

如果你在面试中遇到了这道题，建议按以下节奏展示你的深度：

#### A. 复杂度分析（必谈）
* **堆解法**：$O(N \log K)$。优点是适合**海量数据流**（数据不用一次性加载进内存）。
* **快速选择**：期望 $O(N)$，最坏 $O(N^2)$。面试官会问你：**如何避免最坏情况？**
    * **对策**：引入随机化，即随机选取 `pivot`。

#### B. 空间与原数据的权衡
* 询问面试官：“我是否可以修改原数组？”
    * 如果可以 $\rightarrow$ Quick Select（空间 $O(1)$）。
    * 如果不可以 $\rightarrow$ 堆（空间 $O(K)$）。

#### C. C++ 工程实践
* 你要知道 C++ 标准库里其实自带了这个算法：`std::nth_element`。
* 虽然面试不能只写这一行，但提一句这个函数会显得你对 C++ STL 非常熟悉。

既然我们聊到了 **215. 数组中的第 K 个最大元素** 的 Quick Select 优化，那理解**快速排序 (Quick Sort)** 的标准写法就是基本功了。

快排的核心在于 **Partition（划分）**：选一个基准值（pivot），把小于它的放左边，大于它的放右边。

### 1. 标准快排写法（C++）

这里采用最经典的双指针左右填坑法，逻辑最清晰：

```cpp
void quickSort(vector<int>& nums, int left, int right) {
    if (left >= right) return;

    // 1. Partition 过程
    int i = left, j = right;
    // 职业选手建议：随机选一个 pivot 交换到 nums[left]，防止最坏情况
    int pivot = nums[left]; 

    while (i < j) {
        // 从右向左找第一个小于 pivot 的数
        while (i < j && nums[j] >= pivot) j--;
        if (i < j) nums[i++] = nums[j];

        // 从左向右找第一个大于 pivot 的数
        while (i < j && nums[i] <= pivot) i++;
        if (i < j) nums[j--] = nums[i];
    }
    
    // 此时 i == j，把基准值填回坑里
    nums[i] = pivot;

    // 2. 递归处理左右两部分
    quickSort(nums, left, i - 1);
    quickSort(nums, i + 1, right);
}
```

---

### 2. 为什么在 215 题里它能变成 $O(N)$？

在标准快排里，我们需要递归**左右两边**，所以复杂度是 $O(N \log N)$。
但在找“第 K 大”时，我们只需要递归**一边**：

* 如果 `i` 正好是我们要找的位置，直接收工。
* 如果不是，根据大小关系只去左边**或者**右边。
* 这种逻辑下的时间复杂度推导为：$N + N/2 + N/4 + \dots \approx 2N$，即 **$O(N)$**。

---

### 3. 快排的三个“坑” (面试加分项)

1.  **最坏情况**：如果数组已经有序，选第一个元素做 pivot 会退化成 $O(N^2)$。
    * **对策**：`swap(nums[left], nums[left + rand() % (right - left + 1)])`。
2.  **大量重复元素**：如果数组里全是同一个数，简单的快排也会变慢。
    * **对策**：采用“三路快排”（将数组分为小于、等于、大于三部分）。
3.  **递归深度**：在内核开发等对栈空间极其敏感的场景下，如果递归太深可能导致 **Stack Overflow**。
    * **对策**：当区间较小时（如小于 15 个元素），切换为**插入排序**。

## leetcode 560 Subarray Sum Equals K

你的直觉非常敏锐。**滑动窗口**的灵魂在于“单调性”——即右边界右移总和一定增加，左边界右移总和一定减少。一旦数组中出现了**负数**（或者像这道题，虽然只有正数但你无法通过收缩左边界来单纯“减小”总和以达到目标），窗口的逻辑就会失效。

这道题是 **“前缀和 + 哈希表”** 的经典模板题。

---

### 1. 核心思路：前缀和的逆向思维

假设前缀和 $S[i]$ 表示从开头到索引 $i$ 的元素总和。
如果我们要找一个子数组 $[j, i]$ 使得其和为 $k$，那么：
$$S[i] - S[j-1] = k$$
变形一下：
$$S[j-1] = S[i] - k$$

**翻译成大白话：**
当我遍历到位置 $i$ 时，我手里拿着当前的累积和 $S[i]$。我只需要问哈希表一个问题：“在之前出现过的前缀和里，有多少个值正好等于 $S[i] - k$？”

#### 💻 C++ 实现逻辑

```cpp
int subarraySum(vector<int>& nums, int k) {
    unordered_map<int, int> mp;
    mp[0] = 1; // 基础情况：前缀和正好等于 k 时，S[i]-k = 0
    int count = 0, pre = 0;
    
    for (int x : nums) {
        pre += x; // 计算当前前缀和
        if (mp.count(pre - k)) {
            count += mp[pre - k];
        }
        mp[pre]++; // 记录当前前缀和出现的次数
    }
    return count;
}
```

### 2. 面试官的 Follow-up 会怎么问？

这道题在面试中非常高频，面试官通常会从以下几个维度深挖：

#### A. 空间优化
* **问题**：如果数组非常大，哈希表爆了怎么办？
* **回答**：如果数组只有正数，可以回归到**滑动窗口**（$O(1)$ 空间）。但如果有负数，哈希表是必须的。

#### B. 变体问题（求长度）
* **问题**：如果不求次数，而是求**和为 k 的最长子数组长度**？
* **回答**：哈希表里不再存“次数”，而是存“第一次出现该前缀和的下标”。遇到匹配时，计算 $i - mp[pre-k]$ 取最大值。

#### C. 数据流处理
* **问题**：如果数据是流式输入的，你如何处理？
* **回答**：前缀和加哈希表天然支持流式处理，只需要 $O(1)$ 的单步执行时间。

#### D. 二维扩展
* **问题**：如果在二维矩阵里找和为 $k$ 的子矩形？
* **回答**：这是 Hard 题（LeetCode 1074）。思路是固定上下两行，将二维压缩成一维，再用这道 560 题的解法。
