## leetcode 210 Course Schedule II 

你的直觉很敏锐，这种“必须先做 B 再做 A”的关系在图论中有一个专门的术语：**有向无向环图（DAG）** 里的 **拓扑排序（Topological Sort）**。

虽然“记录路径并遍历关系”的想法接近了核心，但在图论中，这种做法效率较低。我来帮你梳理一下解决这类题目的标准“特种作战”方案。

---

### 🧠 1. 数据结构：关系矩阵 vs 邻接表

你提到了“关系矩阵”，在面试中我们需要根据数据规模做选择：
* **关系矩阵 (Adjacency Matrix)**：`bool matrix[n][n]`。
    * **缺点**：如果课程有 100,000 门，矩阵需要 $10^{10}$ 个位置，内存直接爆掉（$O(N^2)$ 空间）。
* **邻接表 (Adjacency List)**：`vector<vector<int>> adj`。
    * **优点**：只记录存在的边。在面试中，**邻接表是处理图论题的默认选择**，因为它节省空间且遍历邻居极快。

---

### 🚀 2. 核心算法：Kahn 算法（广度优先搜索 BFS）

解决拓扑排序最直观、面试最常用的就是 **Kahn 算法**。它引入了一个关键概念：**入度 (Indegree)**。
* **入度**：指向这个节点的边的数量。在这道题里，`入度 == 0` 代表这门课**没有先修要求**，可以直接上。

#### 算法步骤：
1.  **统计入度**：遍历 `prerequisites`，计算每门课的入度，同时建立邻接表。
2.  **找起点**：把所有 `入度 == 0` 的课全扔进一个**队列 (Queue)**。
3.  **循环处理**：
    * 从队列弹出一门课（这门课可以上了，把它加到结果路径里）。
    * 遍历这门课的所有“后继课”，把它们的**入度减 1**。
    * 如果某门后继课的入度减到 0 了，说明它的先修课都上完了，把它**扔进队列**。
4.  **判断结果**：如果最后结果路径里的课程数等于总课程数，说明成功；否则，说明图中**有环**（死循环），无法完成。

---

### 💻 3. C++ 实现（高效简洁版）

```cpp
class Solution {
public:
    vector<int> findOrder(int numCourses, vector<vector<int>>& prerequisites) {
        vector<vector<int>> adj(numCourses);
        vector<int> indegree(numCourses, 0);
        vector<int> result;
        
        // 1. 建图并统计入度
        for (auto& p : prerequisites) {
            adj[p[1]].push_back(p[0]); // p[1] -> p[0]
            indegree[p[0]]++;
        }
        
        // 2. 将入度为 0 的课入队
        queue<int> q;
        for (int i = 0; i < numCourses; ++i) {
            if (indegree[i] == 0) q.push(i);
        }
        
        // 3. BFS 拓扑排序
        while (!q.empty()) {
            int curr = q.front();
            q.pop();
            result.push_back(curr);
            
            for (int next : adj[curr]) {
                indegree[next]--;
                if (indegree[next] == 0) q.push(next);
            }
        }
        
        // 4. 检查是否有环（结果长度是否等于总课数）
        return result.size() == numCourses ? result : vector<int>();
    }
};
```

### 🛡️ 4. 教练复盘：面试官会追问什么？

1.  **DFS 也能做吗？**
    * 可以。DFS 做法是利用“染色法”记录节点状态（0-未访问，1-访问中，2-访问完）。如果在访问中又遇到了状态为 1 的节点，说明有环。
2.  **为什么要用入度而不是你说的“全路径遍历”？**
    * 全路径遍历（类似回溯）复杂度极高，因为同一个节点会被多次访问。而入度法保证了**每个节点、每条边只被处理一次**，复杂度是完美的 **$O(V + E)$**（节点数 + 边数）。
3.  **实际场景**：
    * 面试官可能会问：这在工程中有什么用？
    * **答**：包管理器（如 `apt` 或 `pip`）处理依赖安装顺序、编译器处理代码文件编译顺序、甚至是 Excel 单元格公式的计算。

你的理解完全正确！这里 `adj[p[1]].push_back(p[0])` 的逻辑正是拓扑排序中**邻接表**的核心设计。

为了让你在面试时能把这个逻辑讲得滴水不漏，我来给你深度拆解一下这个“先驱”与“后继”的关系：

### 1. 为什么是 `p[1] -> p[0]`？
题目给出的 `prerequisites[i] = [a, b]` 表示：想要学习课程 `a` ，必须先学习课程 `b`。
* 在图论的逻辑里，这是一条**从 `b` 指向 `a`** 的有向边。
* **`p[1]`（课程 b）** 是起点（先驱）。
* **`p[0]`（课程 a）** 是终点（后继）。

所以 `adj[p[1]].push_back(p[0])` 的意思就是：**在 `p[1]` 的“后随清单”里加上 `p[0]`**。

### 2. 邻接表存的是什么？
邻接表 `adj` 的每一个索引 `i` 对应的 `vector`，存储的是**所有依赖于课程 `i` 的后续课程**。
* 想象一下：当你上完了课程 `i`，你打开这张清单，告诉清单上的所有课：“你们的先修要求（入度）可以减 1 了！”

### 3. 入度（Indegree）的决定性作用
* **入度 = 0**：代表这门课已经**没有任何先修限制**了，可以立刻“上车”（进入结果序列）。
* **弹出的逻辑**：
    * 我们从队列中弹出一个入度为 0 的课程 `curr`。
    * 它是安全的，所以我们把它放进 `result`。
    * 然后我们去 `adj[curr]` 遍历它所有的“小弟”（后继课程）。
    * 每个“小弟”的入度减 1。**如果某个小弟的入度减到了 0，说明它所有的老大都上完了，它也变安全了，于是入队。**

## leetcode 542 01 Matrix

太棒了！你已经完全掌握了**多源 BFS (Multi-source BFS)** 的神髓。

你的思路非常正确：**把所有的 `0` 当作起跳点，同时向外扩散。** 这就像在水面上同时丢进好几颗石头，涟漪相撞的地方就是最短距离的边界。

### 🔍 诊断你的初稿

你卡住的地方主要是 **“如何记录二维坐标”** 以及 **“如何更新距离”**。

1.  **坐标记录**：队列里建议存 `pair<int, int>` 或者把二维坐标扁平化，否则你只存一个 `i`，没法知道它是哪一行哪一列。
2.  **距离更新**：
    * 我们可以直接在 `result` 矩阵里操作。
    * 初始化时，把所有 `0` 的位置设为 `0`，其他位置设为**最大值**（表示还没走过）。
3.  **扩散逻辑**：从队列弹出一个点，看它上下左右四个邻居。如果邻居的新距离能变得更短，就更新它并把它入队。

---

### 💻 修正后的 C++ 实现

```cpp
class Solution {
public:
    vector<vector<int>> updateMatrix(vector<vector<int>>& mat) {
        int m = mat.size();
        int n = mat[0].size();
        // 1. 初始化结果矩阵，用一个特殊值（如 -1）表示未访问
        vector<vector<int>> dist(m, vector<int>(n, -1));
        queue<pair<int, int>> q;

        // 2. 将所有 0 放入队列，作为 BFS 的第一层
        for (int i = 0; i < m; ++i) {
            for (int j = 0; j < n; ++j) {
                if (mat[i][j] == 0) {
                    dist[i][j] = 0;
                    q.push({i, j});
                }
            }
        }

        // 四个方向的偏移量：上、下、左、右
        int dx[] = {-1, 1, 0, 0};
        int dy[] = {0, 0, -1, 1};

        // 3. 开始多源 BFS 扩散
        while (!q.empty()) {
            auto [curr_x, curr_y] = q.front();
            q.pop();

            for (int i = 0; i < 4; ++i) {
                int next_x = curr_x + dx[i];
                int next_y = curr_y + dy[i];

                // 检查边界 且 必须是未访问过的点（dist == -1）
                if (next_x >= 0 && next_x < m && next_y >= 0 && next_y < n 
                    && dist[next_x][next_y] == -1) {
                    
                    // 距离 = 父亲距离 + 1
                    dist[next_x][next_y] = dist[curr_x][curr_y] + 1;
                    q.push({next_x, next_y});
                }
            }
        }

        return dist;
    }
};
```

### 🛡️ 教练复盘：面试官会追问什么？

1.  **为什么不从 `1` 开始找 `0`？**
    * **答**：如果矩阵里只有一个 `0`，很多个 `1`，那么从每个 `1` 出发做一次 BFS 会导致大量重复计算，复杂度变成 $O(M^2N^2)$。而从所有 `0` 同时出发，每个格子只会被访问一次，复杂度是完美的 **$O(MN)$**。
2.  **这道题能用动态规划（DP）吗？**
    * **答**：**可以！** 这也是这道题的精妙之处。你需要两次扫描：一次从左上到右下，一次从右下到左上。因为距离具有方向传递性。
3.  **空间优化**：
    * 如果面试官要求 $O(1)$ 额外空间（不算返回的矩阵），你可以直接在原矩阵 `mat` 上修改，用一个足够大的数代表未访问。

### 🧠 1. 核心困惑：为什么要用两个数组？

在二维矩阵中，我们通常用 `(row, col)` 来表示一个点。
* `row` 代表行（横向的第几排）。
* `col` 代表列（纵向的第几排）。

如果要访问当前点 `(curr_x, curr_y)` 的上下左右四个邻居，我们通常会写四个 `if` 语句：
```cpp
// 访问上邻居
int up_x = curr_x - 1; // 行号减 1
int up_y = curr_y;     // 列号不变
// ... 检查边界 ...
dist[up_x][up_y] = ...;

// 访问下邻居
int down_x = curr_x + 1; // 行号加 1
int down_y = curr_y;     // 列号不变
// ...

// 访问左邻居
int left_x = curr_x;     // 行号不变
int left_y = curr_y - 1; // 列号减 1
// ...

// 访问右邻居
int right_x = curr_x;     // 行号不变
int right_y = curr_y + 1; // 列号加 1
// ...
```
**这种写法不仅冗长，而且容易写错下标（比如把加减号搞混），在面试中不仅浪费时间，还显得不够“专业”。**

### 🚀 2. 破局之道：坐标偏移量（Delta arrays）

这两个数组 `dx` 和 `dy`，其实是把上面那个冗长的逻辑**数据化**了。

```cpp
// 坐标偏移量：        上   下   左   右
int dx[] = {-1,  1,  0,  0}; // 行号的变化量 (Delta X/Row)
int dy[] = {0,  0, -1,  1}; // 列号的变化量 (Delta Y/Col)
```

我们将 `dx` 和 `dy` 的**同一个索引**组合起来看，就是一个方向的完整偏移：

* **索引 0 (上)**：`(dx[0], dy[0])` 是 `(-1, 0)`。
    * 意味着：新坐标 = `(curr_x - 1, curr_y + 0)`。**这正是上邻居。**
* **索引 1 (下)**：`(dx[1], dy[1])` 是 `(1, 0)`。
    * 意味着：新坐标 = `(curr_x + 1, curr_y + 0)`。**这正是下邻居。**
* **索引 2 (左)**：`(dx[2], dy[2])` 是 `(0, -1)`。
    * 意味着：新坐标 = `(curr_x + 0, curr_y - 1)`。**这正是左邻居。**
* **索引 3 (右)**：`(dx[3], dy[3])` 是 `(0, 1)`。
    * 意味着：新坐标 = `(curr_x + 0, curr_y + 1)`。**这正是右邻居。**

这样，我们就可以用一个简单的 `for` 循环，把四个 `if` 的逻辑统一起来：

```cpp
// 四个方向偏移量
int dx[] = {-1, 1, 0, 0};
int dy[] = {0, 0, -1, 1};

for (int i = 0; i < 4; ++i) {
    // 自动遍历上、下、左、右
    int next_x = curr_x + dx[i];
    int next_y = curr_y + dy[i];
    
    // 统一进行边界和逻辑检查（只需要写一次！）
    if (next_x >= 0 && next_x < m && ... ) {
        // ... 处理邻居逻辑 ...
    }
}
```

## leetcode 46 Permutations

第 46 题（全排列）确实是 **回溯算法（Backtracking）** 的教科书级母题。正如你所说，与其把它当成一道普通的题，不如把它当成一个“模版”或“框架”来背。

回溯的核心思想是：**“一条路走到黑，走不通就回头，回头前记得把脚印擦掉。”**

---

### 🧠 回溯算法的万能框架

我们可以把回溯抽象成一个固定的公式：

```cpp
void backtracking(参数) {
    if (终止条件) {
        存放结果;
        return;
    }

    for (选择：本层集合中元素（树中孩子节点）) {
        处理节点; // 做选择
        backtracking(路径，选择列表); // 递归
        回溯，撤销处理结果; // 撤销选择（擦掉脚印）
    }
}
```

### 💻 46. 全排列（LeetCode 代码实现）

针对这道题，我们需要一个 `used` 数组来标记哪些数字已经被用过了，避免重复选取。

```cpp
class Solution {
public:
    vector<vector<int>> result;
    vector<int> path;

    vector<vector<int>> permute(vector<int>& nums) {
        // used 数组记录每个元素是否被使用过
        vector<bool> used(nums.size(), false);
        backtracking(nums, used);
        return result;
    }

    void backtracking(vector<int>& nums, vector<bool>& used) {
        // 1. 终止条件：路径长度等于数组长度，说明找到了一个全排列
        if (path.size() == nums.size()) {
            result.push_back(path);
            return;
        }

        // 2. 遍历选择列表
        for (int i = 0; i < nums.size(); i++) {
            // 如果这个数已经用过了，直接跳过
            if (used[i]) continue;

            // 3. 做选择
            used[i] = true;
            path.push_back(nums[i]);

            // 4. 递归进入下一层
            backtracking(nums, used);

            // 5. 回溯：撤销选择（非常关键！这是回到上一层的必经之路）
            path.pop_back();
            used[i] = false;
        }
    }
};
```

### 🛡️ 教练的三个灵魂拷问（面试必问）

1.  **为什么要回溯（`pop_back` 和 `used[i]=false`）？**
    * 因为我们是在同一个 `path` 变量上进行操作。如果不撤销，当你返回到上一层准备尝试另一个分支时，`path` 里还残留着之前尝试过的值。
2.  **全排列和子集（Subsets）问题的区别？**
    * 全排列：每层都从 `0` 开始遍历，通过 `used` 数组过滤掉已选元素。
    * 子集/组合：通常需要一个 `startIndex` 参数，保证不再回头选之前的数，防止结果重复。
3.  **时间复杂度是多少？**
    * $O(n!)$。因为排列的可能性是阶乘级别的，这是回溯题目的典型复杂度。

### 💡 如何高效“背”这个框架？

不要死记硬背每一行代码，要记这三个动作：
* **选（Push/True）**

### 🔍 你的初稿修正

1.  **指针类型**：`queue` 里应该存 `TreeNode*`（指针），而不是 `TreeNode`（对象）。否则在 push/pop 时会发生对象拷贝，且无法处理空指针。
2.  **`pop()` 的返回值**：在 C++ `std::queue` 中，`pop()` 是不返回值的。你需要先用 `front()` 获取队头，再 `pop()`。
3.  **分层逻辑（重点）**：你目前的写法会把所有节点按顺序放进一个一维数组。但题目要求返回 `vector<vector<int>>`（每一层是一个独立的数组）。

### 💻 修正后的标准模版

我们需要在 `while` 循环里增加一个**局部循环**，一次性处理掉“当前层”的所有节点。

```cpp
vector<vector<int>> levelOrder(TreeNode* root) {
    if (!root) return {};

    vector<vector<int>> result;
    queue<TreeNode*> q; // 1. 存储指针
    q.push(root);

    while (!q.empty()) {
        // 2. 关键：获取当前层的节点数量
        int size = q.size(); 
        vector<int> currentLevel;

        // 3. 这里的循环保证了我们只处理“这一层”的节点
        for (int i = 0; i < size; i++) {
            TreeNode* node = q.front(); // 获取队头
            q.pop(); // 弹出

            currentLevel.push_back(node->val); // 注意是 node->val

            // 4. 将下一层的孩子放入队列
            if (node->left) q.push(node->left);
            if (node->right) q.push(node->right);
        }

        // 5. 把处理完的一层放入结果集
        result.push_back(currentLevel);
    }
    return result;
}
```

---

### 🛡️ 教练复盘：为什么 `int size = q.size()` 是核心？

这是层序遍历中最精妙的地方：
* 当你进入 `while` 循环时，队列里的节点个数**恰好就是这一层的所有节点**。
* 我们先记录下这个 `size`，然后只循环 `size` 次。
* 在循环过程中，虽然我们会把“下一层”的孩子 push 进去，但它们会被挡在 `for` 循环之外，等待 `while` 的下一次迭代。

### 2. 使用 `->` (箭头操作符) —— 访问“指针指向的对象”
当你手里拿的是一个**地址**（指针），你不能直接点它（因为地址是一个数字，数字没有成员）。`->` 实际上是一个快捷方式，它代表了先**解引用**，再**访问**。

* **场景**：动态分配的对象（`new` 出来的）、函数参数传递的指针。
* **语法**：`指针->成员`（等价于 `(*指针).成员`）

```cpp
TreeNode* nodePtr = new TreeNode(); // nodePtr 是一个地址
nodePtr->val = 10; // 使用 "->" 访问

// 逻辑等价于：
(*nodePtr).val = 10; // 先通过 * 找到那个对象，再点它的成员
```

## leetcode 104 Maxmium Depth of Binary Tree

你的思路非常清晰，直接复用了 **102 层序遍历** 的 BFS 模板来解决深度问题，这在工程实践中是非常稳健的做法！

不过，你的代码中有两个**逻辑小细节**和**语法小瑕疵**需要微调，调整后就能直接 AC 了：

### 🔍 细节诊断

1.  **初始深度与累加时机**：
    * 你初始化 `result = 1`，且在 `while` 循环内部 `result += 1`。
    * **问题**：如果树只有一个根节点，它进入 `while` 处理完这一层后会执行 `result += 1` 变成 `2`，但实际深度应为 `1`。
    * **修正**：通常建议初始化 `result = 0`，每处理完一层（即完成一次 `for` 循环），`result` 加 1。
2.  **返回值类型**：
    * `if (!root) { return {}; }`。
    * **问题**：函数的返回值是 `int`，而 `{}` 在这里会被推导为某种容器。
    * **修正**：空树的深度直接 `return 0;`。
3.  **关于 `pop()` 的理解**：
    * 你的注释写得很好，但在 C++ 中 `q.pop()` 并不返回迭代器（Iterator），它只是单纯地从队列头部删除元素。

---

### 💻 修正后的 BFS 版（迭代）

```cpp
int maxDepth(TreeNode* root) {
    if (!root) return 0; // 空树深度为 0

    int depth = 0; // 从 0 开始计数
    queue<TreeNode*> q;
    q.push(root);

    while (!q.empty()) {
        int size = q.size();
        // 只要进入这个 while，说明这一层一定有节点
        depth++; 
        
        for (int i = 0; i < size; i++) {
            TreeNode* node = q.front();
            q.pop();
            
            if (node->left) q.push(node->left);
            if (node->right) q.push(node->right);
        }
    }
    return depth;
}
```

---

### 🚀 降维打击：递归版（DFS）

虽然你现在的 BFS 写法很熟练，但在面试中，面试官往往会考察你对**递归**的理解。对于这道题，递归（DFS）只需要 **3 行代码**，逻辑美感极强：

**逻辑推导**：
* 整棵树的最大深度 = `max(左子树深度, 右子树深度) + 1`。
* **终止条件**：如果是空节点，深度为 0。

```cpp
int maxDepth(TreeNode* root) {
    if (!root) return 0;
    return max(maxDepth(root->left), maxDepth(root->right)) + 1;
}
```

* **DFS (递归写法)**：像是派两个小弟去探底，谁报上来的数大，我就在谁的基础上加 1。代码极简。

### leetcode 111 Minimum Depth of Binary Tree

### 🔍 为什么你的递归不能 AC？

让我们看一个特殊的例子：如果二叉树长这样（只有右子树，是一条斜线）：
```text
    1
     \
      2
```
* 按照你的代码逻辑：`min(minDepth(NULL), minDepth(Node2)) + 1`。
* `minDepth(NULL)` 返回 **0**。
* 结果就变成了 `min(0, 1) + 1 = 1`。
* **但正确答案应该是 2**！因为最小深度的定义是：从根节点到最近的**叶子节点**（没有左右孩子的节点）。节点 1 不是叶子节点。

---

### 🚀 修正方案：分类讨论

递归求最小深度时，必须处理“单边为空”的情况：

1.  **左空右不空**：最小深度取决于右子树。
2.  **右空左不空**：最小深度取决于左子树。
3.  **左右都不为空**：才使用 `min`。

#### 💻 修正后的递归代码：
```cpp
int minDepth(TreeNode* root) {
    if (!root) return 0;
    
    // 如果左子树为空，右子树不为空，说明要走右边
    if (root->left == nullptr && root->right != nullptr) {
        return minDepth(root->right) + 1;
    }
    // 如果右子树为空，左子树不为空，说明要走左边
    if (root->right == nullptr && root->left != nullptr) {
        return minDepth(root->left) + 1;
    }
    
    // 只有当左右都不为空时，才取最小值
    return min(minDepth(root->left), minDepth(root->right)) + 1;
}
```

### 🛡️ 教练的职业建议：为什么这道题更推荐 BFS？

其实，这道题用你之前熟练的 **BFS（层序遍历）** 才是真正的“降维打击”。

* **理由**：BFS 是按层搜索的。**一旦我们遇到第一个叶子节点，它所在的层数绝对就是整个树的最小深度。** 我们不需要像递归（DFS）那样遍历完每一条路径。

#### 💻 BFS 版（更快、更直观）：
```cpp
int minDepth(TreeNode* root) {
    if (!root) return 0;
    queue<TreeNode*> q;
    q.push(root);
    int depth = 1;

    while (!q.empty()) {
        int size = q.size();
        for (int i = 0; i < size; i++) {
            TreeNode* node = q.front();
            q.pop();

            // 核心：一旦遇到叶子节点，直接返回当前深度
            if (!node->left && !node->right) return depth;

            if (node->left) q.push(node->left);
            if (node->right) q.push(node->right);
        }
        depth++;
    }
    return depth;
}
```

### 🚨 结论先行：层序遍历 = BFS

* **层序遍历 (Level Order Traversal)** 属于 **BFS (Breadth-First Search，广度优先搜索)**。
* **前/中/后序遍历 (Pre/In/Post Order)** 属于 **DFS (Depth-First Search，深度优先搜索)**。

---

### 1. 为什么层序遍历是 BFS？

想象你在一个水池里丢了一块石头：
* **BFS (广度优先)**：就像水波纹，从中心向外**一层一层**地扩散。它强调的是“横向发展”，先看完所有距离为 1 的，再看距离为 2 的。
* **层序遍历**：正是这种逻辑。你先处理根（第 1 层），再处理它的所有孩子（第 2 层），再处理所有孙子（第 3 层）。
* **工具**：BFS 必须借助 **队列 (Queue)** 来实现“先看先扩散”。

---

### 2. 什么是 DFS？

想象你在探险一个未知的洞穴：
* **DFS (深度优先)**：你碰到岔路口，会选一条路**一直走到黑**，直到撞墙（叶子节点），然后再退回来换另一条路。它强调的是“纵向深入”。
* **前/中/后序遍历**：就是 DFS。比如前序遍历，你会一路沿着左孩子钻到底，然后再慢慢回溯。
* **工具**：DFS 通常借助 **递归**（利用函数调用栈）或 **显式栈 (Stack)** 来实现。

---

### 3. 一个直观的对比表格

| 特性 | **BFS (层序遍历)** | **DFS (前/中/后序)** |
| :--- | :--- | :--- |
| **搜索方式** | 一层一层横向搜 | 一条路钻到底再回头 |
| **数据结构** | **队列 (Queue)** | **栈 (Stack) / 递归** |
| **典型应用** | 最短路径、最小高度、层序输出 | 路径搜索、拓扑排序、树的直径 |
| **你的代码** | 你用 `while + queue` 写的 102/104 | 你用 `return max(...) + 1` 写的递归 |
