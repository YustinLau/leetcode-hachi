## leetcode 10 Regular Expression Matching

面试官说得很对，**LeetCode 10 (正则表达式匹配)** 是动态规划（DP）中的“大魔王”级题目。它的难点不在于代码长短，而在于处理 `*` 号时，状态转移方程极其复杂。

### 🧠 1. 核心思路：二维 DP 的定义

既然是两个字符串（`s` 和 `p`）的匹配，自然想到用二维数组 `dp[i][j]`。

* **定义**：`dp[i][j]` 表示 `s` 的前 `i` 个字符和 `p` 的前 `j` 个字符是否匹配。
* **目标**：求 `dp[s.size()][p.size()]`。

---

### 🚀 2. 状态转移方程（重点中的重点）

当我们看 `p[j-1]`（第 $j$ 个字符）时，分两种情况讨论：

#### 情况 A：`p[j-1]` 不是 `*`
这种很简单，只要当前字符匹配，且之前的也匹配就行。
$$dp[i][j] = dp[i-1][j-1] \quad \text{if } (s[i-1] == p[j-1] \text{ or } p[j-1] == '.')$$

#### 情况 B：`p[j-1]` 是 `*`
这是这道题最绕的地方。`*` 必须和它前面的字符（即 `p[j-2]`）结合使用。它有两种选择：

1.  **匹配 0 次**：相当于把 `x*` 整个丢弃。
  $$dp[i][j] = dp[i][j-2]$$
1.  **匹配 1 次或多次**：前提是 `s[i-1]` 必须能被 `p[j-2]` 匹配。如果匹配成功，我们保持 `p` 不变，继续看 `s` 的前一个字符。
  $$dp[i][j] = dp[i-1][j] \quad \text{if } (s[i-1] == p[j-2] \text{ or } p[j-2] == '.')$$

---

### 💻 3. C++ 代码实现

```cpp
class Solution {
public:
    bool isMatch(string s, string p) {
        int m = s.size(), n = p.size();
        // dp[i][j] 代表 s的前i个字符和p的前j个字符是否匹配
        vector<vector<bool>> dp(m + 1, vector<bool>(n + 1, false));

        // 1. 初始化
        dp[0][0] = true; 
        
        // 特殊处理：s为空，p不为空的情况（例如 s="", p="a*b*" 是匹配的）
        for (int j = 2; j <= n; j++) {
            if (p[j-1] == '*') {
                dp[0][j] = dp[0][j-2];
            }
        }

        // 2. 开始填表
        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                if (p[j-1] != '*') {
                    // 普通匹配或 '.' 匹配
                    if (s[i-1] == p[j-1] || p[j-1] == '.') {
                        dp[i][j] = dp[i-1][j-1];
                    }
                } else {
                    // 遇到 '*'，分两种大情况
                    // 情况1：匹配0次，直接看去掉 'x*' 之后的情况
                    dp[i][j] = dp[i][j-2];
                    
                    // 情况2：匹配1次或多次，前提是当前字符得对得上
                    if (s[i-1] == p[j-2] || p[j-2] == '.') {
                        // 只要匹配0次或多次有一种成功，dp[i][j] 就是 true
                        dp[i][j] = dp[i][j] || dp[i-1][j];
                    }
                }
            }
        }
        return dp[m][n];
    }
};
```

你的观察非常敏锐。处理 DP 的时候，边界感就是生命线。我们来深度拆解一下这两个点。

### 1. 关于 `dp[i][j-2]` 的越界问题

**你的直觉是对的。** 这里的安全保障主要来自两个层面：

* **语义层面的必然**：在正则表达式中，`*` 永远不可能出现在 `p` 的首位（比如 `p = "*abc"` 是非法的），它必须跟在一个有效字符后面。因此，如果 `p[j-1]` 是 `*`，那么 `j` 至少是 **2**（代表 `p` 的第二个字符）。
* **代码层面的保护**：
    * 在**初始化**阶段，循环是从 `j = 2` 开始的：`for (int j = 2; j <= n; j++)`。
    * 在**填表**阶段，虽然 `j` 从 1 开始，但只有当 `p[j-1] == '*'` 时才会访问 `dp[i][j-2]`。正如上面所说，由于 `*` 不会是第一个字符，当 `p[j-1]` 是 `*` 时，`j-1` 至少是 1，所以 `j` 至少是 2，`j-2` 最低也是 0，**不会越界**。

---

### 2. 深度理解 `*` 的两种大情况

`*` 是这道题的灵魂。我们要把 `X*`（某个字符+星号）看作一个**整体能量包**。

#### 情况 1：匹配 0 次（扔掉能量包）
**逻辑**：我不指望这个 `X*` 能匹配任何东西，直接把它从 `p` 中删掉。
**表达式**：`dp[i][j] = dp[i][j-2]`
* **例子**：`s = "b"`, `p = "ba*"`
    * 当我们看 `s[0]`('b') 和 `p[2]`('*') 时。
    * 选匹配 0 次，看 `s` 的前 1 个字符 ("b") 和 `p` 的前 1 个字符 ("b")。
    * **匹配成功！** `dp[1][3] = dp[1][1] = true`。

#### 情况 2：匹配 1 次或多次（消耗能量包）
**逻辑**：如果 `s` 当前的末尾字符能被 `X*` 里的 `X` 盖住，那我们就试着把 `s` 的末尾字符去掉，看看剩下的 `s` 能不能接着被这个 `X*` 匹配。
**表达式**：`dp[i][j] = dp[i-1][j]`（前提是 `s[i-1]` 匹配 `p[j-2]`）
* **重点理解**：为什么是 `dp[i-1][j]` 而不是 `dp[i-1][j-2]`？
    * 因为 `*` 可以匹配**多次**。我们消耗了 `s` 的一个字符，但我们要**保留** `p` 里的 `X*`，因为它可能还能继续匹配 `s` 剩下的部分。
* **例子**：`s = "aaa"`, `p = "a*"`
    1.  看 `s[2]`('a') 和 `p[1]`('*')。字符匹配，看 `dp[i-1][j]`，即 `s="aa"` 和 `p="a*"` 是否匹配。
    2.  再看 `s[1]`('a') 和 `p[1]`('*')。字符匹配，看 `dp[i-2][j]`，即 `s="a"` 和 `p="a*"` 是否匹配。
    3.  最后 `s` 空了，通过初始化时的 `dp[0][j]` 逻辑完成闭环。

---

### 💡 教练的“大白话”总结

你可以把 `dp[i][j]` 想象成在玩接龙：

* **如果是普通字符**：你得跟我长得一样，我才让你接在后面（`dp[i-1][j-1]`）。
* **如果是 `*` 号**：
    * 我可以**装死**：你就当我没出现过，看看之前的能不能接上（`dp[i][j-2]`）。
    * 我可以**变身**：如果我前面的字符跟你末尾一样，你就把末尾去掉，看看剩下的还能不能跟我变出来的分身接上（`dp[i-1][j]`）。

这是一个非常深刻的问题。在算法面试和实际开发中，**递归（Recursion）** 并不是为了让代码看起来更高级，而是一种**处理复杂逻辑的降维打击工具**。

你可以把递归想象成“套娃”。总结来说，当你的问题满足以下**四个特征**时，就该条件反射地想到递归：

---

### 1. 结构具有“自相似性”（子问题相同）
如果一个大问题可以拆解成若干个小问题，且这些**小问题的解决方法与大问题完全一样**，这就是递归的温床。
* **例子**：计算 $n!$。
    * 计算 $n!$ 的方法是 $n \times (n-1)!$。
    * 计算 $(n-1)!$ 的方法又是 $(n-1) \times (n-2)!$。
    * 逻辑完全一致，只是规模变小了。

### 2. 数据结构天然定义为递归
很多高级数据结构的定义本身就是递归的，处理它们时，递归通常是**最优解**。
* **二叉树**：一个根节点，左右孩子又是二叉树。所以遍历、求深度、找祖先，递归最顺手。
* **链表**：一个节点，后面跟着一个链表（虽然常用迭代，但递归写起来极简）。
* **文件系统**：一个文件夹，里面包含文件和文件夹。

### 3. 需要“回溯”或“深度搜索”
当你需要尝试所有可能性，且在发现一条路走不通时需要**返回到上一步**继续尝试时，递归（结合回溯）是唯一的选择。
* **例子**：**LeetCode 46 全排列**、**迷宫寻路**。
    * 递归的“函数调用栈”会自动帮你记住“你是从哪儿来的”，你不需要手动记录每一步的返回路径。

### 4. 问题的答案依赖于子问题的结果（自底向上）
如果你想知道现在的状态，必须先知道“前一个”或“后几个”状态。
* **例子**：**动态规划（DP）** 的递归实现（记忆化搜索）。
    * 比如 `isMatch(s, p)`，你想知道当前是否匹配，取决于去掉一个字符后是否匹配。

---

### 🛡️ 职业选手的“避坑”指南
虽然递归很美，但面试官会盯着你的**空间复杂度**。决定用递归前，先过一下这三道关卡：

1.  **是否有终止条件（Base Case）？**
    * 没有终止条件的递归会造成 `Stack Overflow`（栈溢出）。
2.  **递归深度是否可控？**
    * 如果树的高度是 $10^5$，递归可能会爆栈。这时候面试官会暗示你改用 **迭代（Iteration）+ 显式栈（Stack）**。
3.  **是否有大量重复计算？**
    * 比如斐波那契数列，不加“备忘录”的递归是 $O(2^n)$，那是自杀式写法。

---

### 💡 总结成一句话
> **如果你发现处理当前这一步的逻辑，和处理剩下部分的逻辑一模一样，且剩下部分规模更小，那就递归吧。**

非常棒的追问！这正是动态规划（DP）初学者最容易产生混淆的地方：**“下标偏移”**。

在算法界，我们经常面临“人的思维（从1开始数）”和“数组的索引（从0开始数）”之间的冲突。我来帮你把这个逻辑彻底对齐。

---

### 1. 为什么定义是 `dp[m+1][n+1]`？
**`dp[i][j]` 的含义是：** `s` 的前 `i` 个字符，和 `p` 的前 `j` 个字符，是否匹配。

* **“前 0 个字符”**：代表**空字符串**。
* **“前 $m$ 个字符”**：代表**整个字符串**。
这就是为什么我们要开 `m+1` 大小的空间。`dp[m][n]` 存储的就是“`s` 全长”和“`p` 全长”的匹配结果。

---

### 2. 为什么一会儿说 `j-1` 一会儿说 `j`？
这是为了在代码里正确地找到字符。

* **在 DP 表里**：我们讨论的是第 $i$ 个**状态**。
* **在原始字符串里**：`s` 的第 $i$ 个字符，其索引是 `s[i-1]`（因为数组下标从 0 开始）。

| 概念 | 逻辑描述 | 代码中的索引 |
| :--- | :--- | :--- |
| **状态** | `s` 的前 $i$ 个字符 | `dp[i][...]` |
| **字符** | `s` 的第 $i$ 个字符 | `s[i-1]` |

**所以当你看到代码里写：**
`if (s[i-1] == p[j-1]) { dp[i][j] = dp[i-1][j-1]; }`
**翻译成人话就是：**
“如果 `s` 的**第 $i$ 个**字符等于 `p` 的**第 $j$ 个**字符，那么‘前 $i$ 个’是否匹配，取决于‘前 $i-1$ 个’是否匹配。”

---

### 3. 重新审视 `*` 的表达式
我们再用这个逻辑梳理一遍 `p[j-1] == '*'` 的情况。此时我们看的是 `p` 的第 $j$ 个字符，它是个星号。

* **匹配 0 次**：
    `dp[i][j] = dp[i][j-2]`
    （前 $i$ 个 `s` 能否匹配 前 $j$ 个 `p`，取决于前 $i$ 个 `s` 能否匹配**去掉星号及其前导符后**的 `p`，即前 $j-2$ 个。）

* **匹配 1 次或多次**：
    `if (s[i-1] == p[j-2]) { dp[i][j] = dp[i-1][j]; }`
    （如果 `s` 的**当前第 $i$ 个**字符，能被星号前面的那个字符（**第 $j-1$ 个**，索引为 `p[j-2]`）匹配，那么结果取决于 `s` 去掉末尾后（前 $i-1$ 个）是否能接着跟这个星号匹配。）

---

### 💡 一个表格看清下标对应关系

假设 `s = "abc"`，`m = 3`：

| $i$ (状态) | 代表字符串 | 对应 `s` 的下标 |
| :--- | :--- | :--- |
| 0 | "" (空) | (无) |
| 1 | "a" | `s[0]` |
| 2 | "ab" | `s[1]` |
| 3 | "abc" | `s[2]` |

**结论**：`dp[m][n]` 实际上就是 `dp[3][...]`，它代表了整个字符串。

---

### 🛡️ 总结这个“套路”
以后你写任何双字符串的 DP（如：最长公共子序列、编辑距离、正则表达式），都可以直接套用：
1.  **空间**开 `n+1`。
2.  **`dp[i][j]`** 代表长度。
3.  **`s[i-1]`** 代表当前字符。

这样你就再也不会被 $i$ 和 $i-1$ 搞晕了！

## leetcode 322 Coin Change

你的直觉非常敏锐！你刚才提到的这种写法，实际上是动态规划中极其经典的**“空间优化”**结果。

在 LeetCode 322（零钱兑换）中，使用一维数组不仅能解决问题，而且是该题的标准最优解。之所以你觉得“和硬币种类长度 $n$ 没关系了”，是因为硬币的维度被**压缩**到了循环里。

---

### 🧠 1. DP 数组的真正含义

正如你所想：
* **定义**：`dp[i]` 代表凑齐金额 `i` 所需的最少硬币个数。
* **目标**：求 `dp[amount]`。

### 🚀 2. 状态转移方程：从“选择”出发

虽然你定义了一维数组，但**硬币种类**并没有消失，它变成了你每一个金额下的**“选择”**。

对于每一个金额 `i`，你有 $n$ 种选择（即 $n$ 种硬币）。
如果你选择了一枚面值为 `coin` 的硬币，那么：
$$dp[i] = dp[i - coin] + 1$$
我们要找的是所有选择中的**最小值**。

---

### 💻 3. 代码实现（感受 $n$ 的存在）

你会发现，硬币种类的长度 $n$ 体现在了**内层循环**里。

```cpp
class Solution {
public:
    int coinChange(vector<int>& coins, int amount) {
        // 1. 初始化：dp[i] 最大不会超过 amount（全是1元），所以初始化为 amount + 1
        vector<int> dp(amount + 1, amount + 1);
        dp[0] = 0; // 凑齐 0 元需要 0 个硬币

        // 2. 遍历每一个金额（外层：背包容量）
        for (int i = 1; i <= amount; i++) {
            // 3. 遍历每一种硬币（内层：物品选择）
            for (int coin : coins) {
                if (i - coin >= 0) { // 只有当前金额大于硬币面值时才能选
                    // 状态转移：选这个硬币 vs 不选这个硬币（保持原样）
                    dp[i] = min(dp[i], dp[i - coin] + 1);
                }
            }
        }

        // 如果最终值没被更新，说明凑不出来，返回 -1
        return dp[amount] > amount ? -1 : dp[amount];
    }
};
```

---

### 🛡️ 4. 教练复盘：为什么感觉和 $n$ 没关系了？

其实这道题本质上是一个**完全背包问题**（物品可以无限次取用）。

* **原始二维 DP**：`dp[i][j]` 代表使用前 `i` 种硬币凑齐金额 `j` 的最小个数。
* **空间优化原理**：因为计算 `dp[i][j]` 时只依赖于同一行左边的值（已经计算过的当前硬币结果）或上一行的值。通过**从左向右**遍历，我们可以直接用一维数组覆盖掉旧的数据。

**面试官的 Follow-up 预警：**
1. **为什么要初始化为 `amount + 1`？**
   答：因为凑齐金额的最坏情况是全是 1 元硬币，数量为 `amount`。`amount + 1` 相当于无穷大，方便 `min` 函数比较。
2. **如果硬币只能用一次（0-1背包），循环顺序需要变吗？**
   答：非常关键！如果是 0-1 背包，内层循环必须**从右向左**遍历，以防止同一个硬币被重复计算。

---

### 💡 总结

你觉得“没关系了”，是因为你跳过了二维 DP 的中间步骤，直接写出了**空间复杂度为 $O(amount)$** 的高效版本。

* **$O(amount)$** 是数组长度。
* **$O(n)$** 隐藏在内层循环里。
* **总时间复杂度**：$O(n \times amount)$。

## leetcode 44 WildCard Matching

你的思路非常连贯！LeetCode 44（通配符匹配）和第 10 题确实是“孪生兄弟”，但它们的 `*` 含义完全不同，这直接导致了转移方程的差异：

* **第 10 题的 `*`**：必须配合前一个字符使用（`a*` 是一个整体）。
* **第 44 题的 `*`**：**独立存在**，可以匹配**任意长度**的字符串（包括空串）。

让我们根据这个差异，把你的代码细节补全。

---

### 1. 初始化部分的细节
你写的 `dp[0][j] = dp[0][j-1]` 是正确的。它的意思是：如果 `p` 的当前字符是 `*`，那么它能不能匹配空串，取决于它前面的部分能不能匹配空串。
**不需要其他特殊处理**，因为 `s` 不为空而 `p` 为空的情况（`dp[i][0]`）默认就是 `false`，符合逻辑。

---

### 2. 核心逻辑：当 `p[j-1]` 是 `*` 时
在第 44 题中，`*` 的能力非常强，它只有两种选择：

1.  **不使用这个 `*`**：匹配空串。
    * `dp[i][j] = dp[i][j-1]`（看 `p` 的前一个状态）。
2.  **使用这个 `*`**：匹配至少一个字符。
    * `dp[i][j] = dp[i-1][j]`（看 `s` 的前一个状态）。
    * *理解：* 只要 `s` 的前一个字符能被这个 `*` 搞定，那么现在的 `s[i-1]` 也能被同一个 `*` 搞定。

**所以，只要满足其一即可：**
`dp[i][j] = dp[i][j-1] || dp[i-1][j];`

---

### 3. 补全后的完整代码

注意：这道题里的 `?` 相当于第 10 题里的 `.`。

```cpp
bool isMatch(string s, string p) {
    int m = s.size();
    int n = p.size();
    vector<vector<bool>> dp(m + 1, vector<bool>(n + 1, false));
    
    dp[0][0] = true;

    // 1. 初始化：处理 s 为空的情况
    for (int j = 1; j <= n; j++) {
        if (p[j-1] == '*') {
            dp[0][j] = dp[0][j-1];
        }
    }

    // 2. 填表
    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (p[j-1] == '*') {
                // * 的两种情况：
                // dp[i][j-1]: * 匹配空串，跳过它
                // dp[i-1][j]: * 匹配了当前 s[i-1]，且可以继续匹配剩下的 s
                dp[i][j] = dp[i][j-1] || dp[i-1][j];
            } else if (p[j-1] == '?' || s[i-1] == p[j-1]) {
                // 普通匹配或 ? 匹配：看左上方
                dp[i][j] = dp[i-1][j-1];
            }
            // 其余情况默认为 false
        }
    }
    return dp[m][n];
}
```

---

### 🛡️ 为什么 `s="aaa", p="a*"` 能过？

我们来手动模拟一下这个逻辑：
1.  当 `i=1, j=2` (`s="a", p="a*"`)：
    * `p[1]` 是 `*`。
    * `dp[1][2] = dp[1][1] || dp[0][2]`。
    * 因为 `dp[1][1]` (a对a) 是 `true`，所以 `dp[1][2]` 是 `true`。
2.  当 `i=2, j=2` (`s="aa", p="a*"`)：
    * `dp[2][2] = dp[2][1] || dp[1][2]`。
    * 因为我们刚算出来 `dp[1][2]` 是 `true`，所以 `dp[2][2]` 也是 `true`。

**这就是 `dp[i-1][j]` 的威力**：它实现了“接力棒”式的匹配。

---

### 💡 总结：10 题 vs 44 题

* **第 10 题 (`x*`)**：星号是附庸，看 `j-2`（跳过包）或 `i-1`（消耗包）。
* **第 44 题 (`*`)**：星号是独立大将，看 `j-1`（跳过星号）或 `i-1`（星号吞噬一个字符）。

## leetcode 72 Edit Distance

这是一个非常经典的问题。首先回答你关于“谁变谁”的疑惑：**在编辑距离中，Word1 变成 Word2，和 Word2 变成 Word1 的最小步数是完全相等的。** 这是因为增加操作的逆向就是删除，替换的逆向还是替换。所以我们统一固定为：**通过操作 Word1 来匹配 Word2**。

### 🧠 1. DP 数组的含义与初始化

* **`dp[i][j]`**：代表 `word1` 的前 `i` 个字符变成 `word2` 的前 `j` 个字符所需的最少操作数。
* **初始化（Base Case）**：
    * 如果 `word2` 是空的，`word1` 需要删除所有字符：`dp[i][0] = i`。
    * 如果 `word1` 是空的，`word1` 需要增加所有字符：`dp[0][j] = j`。

---

### 🚀 2. 状态转移方程：三种操作的本质

当我们看 `word1[i-1]` 和 `word2[j-1]` 时，如果它们**已经相等**，不需要任何操作：
`dp[i][j] = dp[i-1][j-1]`

如果它们**不相等**，我们有三种选择（取其中的最小值，再 **+1**）：

1.  **替换 (Replace)**：把 `word1[i-1]` 换成 `word2[j-1]`。
    * 状态回到：`dp[i-1][j-1] + 1`
2.  **删除 (Delete)**：把 `word1[i-1]` 删掉。
    * 相当于用 `word1` 的前 `i-1` 个去匹配 `word2` 的前 `j` 个。
    * 状态回到：`dp[i-1][j] + 1`
3.  **插入 (Insert)**：在 `word1` 末尾插入一个跟 `word2[j-1]` 一样的字符。
    * 相当于 `word1` 的前 `i` 个已经匹配了 `word2` 的前 `j-1` 个。
    * 状态回到：`dp[i][j-1] + 1`

---

### 💻 3. C++ 实现

```cpp
int minDistance(string word1, string word2) {
    int m = word1.size();
    int n = word2.size();
    // 1. 定义 DP，初始化大小
    vector<vector<int>> dp(m + 1, vector<int>(n + 1));

    // 2. 初始化边界逻辑
    for (int i = 0; i <= m; i++) dp[i][0] = i; // word1 -> 空
    for (int j = 0; j <= n; j++) dp[0][j] = j; // 空 -> word2

    // 3. 填表
    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (word1[i-1] == word2[j-1]) {
                // 字符相同，不用动
                dp[i][j] = dp[i-1][j-1];
            } else {
                // 字符不同，从三种操作里选步数最少的
                // min(左边-插入, 上面-删除, 左上-替换) + 1
                dp[i][j] = min({dp[i-1][j], dp[i][j-1], dp[i-1][j-1]}) + 1;
            }
        }
    }
    return dp[m][n];
}
```

### 🛡️ 教练复盘：面试官在看什么？

    * 很多同学会混淆 `dp[i-1][j]` 和 `dp[i][j-1]`。记住：**`i-1` 代表 `word1` 变短了（删了），`j-1` 代表 `word2` 的需求变少了（加了）**。
* **初始化细节**：
    * 别忘了 `dp[0][0] = 0`。
* **理解“步数”**：
    * 为什么替换是 `dp[i-1][j-1] + 1`？因为你把 `word1[i-1]` 换了之后，当前这个位置就对齐了，剩下的就是处理 `i-1` 和 `j-1` 的事了。

---

### 1. 为什么替换是 `dp[i-1][j-1] + 1`？

假设：`word1 = "ros"`, `word2 = "hot"`，我们要看 `s` 变成 `t`。此时 `i=3, j=3`。

* **当前状态**：你想把 `word1` 的第 3 个字符 `'s'` 替换成 `word2` 的第 3 个字符 `'t'`。
* **执行操作**：付出了 **+1** 的代价，把 `'s'` 变成了 `'t'`。
* **操作后的结果**：
    * `word1` 变成了 `"rot"`。
    * 你看，此时两个单词的**末尾已经强行对齐了**（都是 `'t'`）。
* **剩下的任务**：既然末尾对齐了，剩下的步数就取决于 `word1` 的前 2 个字符 (`"ro"`) 变成 `word2` 的前 2 个字符 (`"ho"`) 需要多少步。
* **对应坐标**：这正是 **`dp[i-1][j-1]`**。

> **核心逻辑**：替换一个字符，相当于**同时消耗**掉了两个单词的末尾。

---

### 2. 为什么插入是 `dp[i][j-1] + 1`？

这个最容易绕晕。请记住：**我们是在操作 `word1`。**

假设：`word1 = "ab"`, `word2 = "abc"`。此时 `i=2, j=3`。

* **当前状态**：`word1` 只有 `"ab"`，而 `word2` 需要 `"abc"`。
* **执行操作**：你在 `word1` 的末尾**插入**了一个 `'c'`。
* **操作后的结果**：
    * `word1` 变成了 `"abc"`。
    * **重点来了**：插入的这个 `'c'` 已经完美匹配了 `word2` 的最后一个字符（第 `j` 个字符）。
* **剩下的任务**：既然 `word2` 的第 `j` 个字符已经搞定了，我们需要知道：`word1` **原来的**那 2 个字符（`"ab"`），去匹配 `word2` **剩下的**前 2 个字符（也是 `"ab"`）需要多少步。
* **对应坐标**：
    * `word1` 还是原来的前 $i$ 个（并没有因为插入而减少原有的字符）。
    * `word2` 的需求减少了 1 个（变成了前 $j-1$ 个）。
    * 所以是 **`dp[i][j-1]`**。

---

### 3. 顺便理清：删除为什么是 `dp[i-1][j] + 1`？

假设：`word1 = "abcd"`, `word2 = "abc"`。此时 `i=4, j=3`。

* **执行操作**：你把 `word1` 的末尾 `'d'` 删掉了。
* **操作后的结果**：
    * `word1` 剩下了 `"abc"`。
* **剩下的任务**：你需要知道 `word1` **剩下的**这 3 个字符，去匹配 `word2` **原有的** 3 个字符需要多少步。
* **对应坐标**：
    * `word1` 变短了，看前 **$i-1$** 个。
    * `word2` 没变，还是前 **$j$** 个。
    * 所以是 **`dp[i-1][j]`**。

---

### 💡 教练的“暴力记忆法”

如果在面试时紧张了，你可以这样想：

* **`dp[i-1][j-1]` (左上)**：两个单词各退一步，代表**替换**（或者字符本身相等）。
* **`dp[i-1][j]` (上方)**：只有 `word1` 退了一步，代表 `word1` 变短了 $\rightarrow$ **删除**。
* **`dp[i][j-1]` (左方)**：只有 `word2` 的需求退了一步，代表 `word1` 帮它补了一个字符 $\rightarrow$ **插入**。
